# Slides artifact 0.1.0

A deck that complies with this spec is a directory whose `metadata.json` says `"specVersion": "0.1.0"` and whose files match the layout below. Metadata is JSON. Slide copy is Markdown.

## Deck directory

```text
.artifacts/slides-{name}/
├── metadata.json
├── assets/
│   ├── default.css
│   ├── custom.css          optional
│   └── …                   images and other media
└── slides/
    ├── 1/
    │   ├── content.md
    │   ├── speaker-notes.md
    │   ├── metadata.json
    │   └── custom.css      optional
    └── 2/
        └── …
```

Slide order is the folder name: `1`, `2`, `3`, with no leading zeros and no gaps. There is no separate order field. Reorder by renaming the folders.

`assets/default.css` is required. It is the layout snapshot copied in when the deck is created. `assets/custom.css` exists only when the deck theme differs from that snapshot. A slide's `custom.css` exists only when that slide differs from its slide template.

## Deck metadata.json

| Field | Required | Meaning |
|---|---|---|
| `specVersion` | yes | `"0.1.0"` |
| `title` | yes | Deck title |
| `description` | yes | One line on what the deck is for |
| `template` | yes | Deck template name: `briefing`, `research-readout`, `design-review`, `user-journey`, or `vision` |
| `aspectRatio` | yes | `"16:9"` |
| `status` | yes | `draft` or `published` |
| `createdAt` | yes | ISO-8601 timestamp |
| `updatedAt` | yes | ISO-8601 timestamp |
| `canonical` | when published | `{ "target", "url", "publishedAt" }` |
| `models` | no | Models that authored or revised this deck |
| `agents` | no | Agents or skills that authored or revised this deck |

`canonical.target` is `google-slides` or `figma-slides`. `canonical.url` is an `https` URL. `status` is `published` only after that URL exists. Editing the deck sets `status` back to `draft` and leaves `canonical` in place.

`models` and `agents` are lists. Each entry is `{ "id", "description" }`. `id` is the identifier the tool reports, such as `claude-sonnet-4.6` or `uxd-slides-create`. `description` is one line on what that model or agent did. Omit a list when nothing is known. Keep earlier entries when a later model or agent revises the deck, so a reader can see whether the deck was made with a model that is now old.

## Slide folder

Each numbered folder contains:

| File | Required | Meaning |
|---|---|---|
| `content.md` | yes | Visible copy |
| `speaker-notes.md` | yes | Speaker notes. May be empty. Not drawn on the slide. |
| `metadata.json` | yes | Slide template and presentation fields |
| `custom.css` | no | Rules that apply only to this slide |

### Slide metadata.json

| Field | Required | Meaning |
|---|---|---|
| `template` | yes | `title`, `section`, `content`, `split`, `quote`, `beat`, `closing`, `agenda`, `persona`, `stages`, `scene`, or `compare` |
| `kicker` | no | Small label above the heading |
| `image` | no | Deck-relative path such as `assets/screen.png`, for `split` and `beat` |

### content.md

- One `#` heading. Required except on a `quote` slide that contains a quotation.
- One `##` subheading.
- `###` group labels. A `beat` uses `Users this serves`, `Unmet needs this addresses`, and `Solutions we deliver`, in that order.
- `-` bullets. Five or fewer, except on a beat.
- `>` for a quotation.
- `![alt](assets/file.png)` for an inline image.
- One fenced code block when the audience needs the source text.
- `**bold**`, `` `code` ``, and `[label](https://...)` inside a line.

Image paths start with `assets/` and point at a file in the deck. Remote and absolute paths are not part of this spec. Tables are not part of this spec.

## Theme

`assets/default.css` defines the layouts, including `--slide-accent`. Deck-wide changes go in `assets/custom.css` and override those variables. Per-slide changes go in that slide's `custom.css`.

The viewer does not load fonts from the network.

## Viewer files

Export may add `index.html`, `viewer.css`, `viewer.js`, `deck.json`, `export-manifest.json`, and `slide-overrides.css` to the deck directory. Those files are a build of this spec. They are not required for the deck to comply, and they are not a second source of truth. `slides/` and `metadata.json` are the source of truth.
