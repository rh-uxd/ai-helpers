# Problem brief

A problem brief is the agreed frame for a product problem: who is affected, what happens today, which claims are evidence, and what sits inside the scope. [NN/g's problem statement](https://www.nngroup.com/articles/problem-statements/) is the same idea. The statement is a scoping and alignment tool. It describes the current condition. Capabilities, screens, and a prototype come later, in other skills.

**Contract:** [SKILL.md](SKILL.md)

## What you leave with

- A problem statement with no solution in it
- The person, their goal, and the current condition
- A desired outcome stated as a change in that condition
- Evidence and assumptions, labeled
- One situation in scope, plus known constraints
- The people who need to agree this is the problem
- For vision work, separate provisional As-Is and To-Be map starters using the playbook's lanes and matching `S#` stage columns

## What this skill asks for

A problem, a feature request, or an existing discovery brief, and whatever evidence you already have. New research is optional. If `uxd-discovery` has already framed the work for research, start from that brief.

## Workshop

**Customer profile (about 45 minutes, with a product or engineering partner).** Use the customer side of Alexander Osterwalder’s [Value Proposition Canvas](https://www.strategyzer.com/resources/canvas-tools-guides/the-value-proposition-canvas): jobs, pains, and gains. Put research quotes on the pains. Unaddressed pains mark the edge of scope.

The value-map side of that canvas, where capabilities show up, is input to `uxd-experience-narrative-create`, not to this brief.

Common miss: writing the feature you want to build as if it were the problem.

## Where the other pieces go

| Piece | Where it is captured |
|-------|----------------------|
| Enabling capabilities and time horizon | The brief's separate Vision handoff for the provisional Journey starter; the narrative builds on the context the team supplied |
| Screens and a prototype | `uxd-experience-narrative-create`, then `uxd-prototype-create` |
| Stakeholder demo plan | `uxd-experience-review` |

A vision is those artifacts together. UXD assist keeps the checklist and will ask only for the next one that is missing.
