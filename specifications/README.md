# Specifications

This directory documents the formats of artifacts generated by skills in this repository, such as slide decks, prototypes, canvases, and docs. Each specification defines the folder structure, required files, and fields those files contain. Together, these rules describe what makes an artifact compatible with tools that support that format.

## Why specifications are needed

As more skills generate and work with artifacts, they need a shared format to rely on. A skill that updates a slide deck needs to find its slide content. A CI script might check for required metadata. A viewer needs to know where the speaker notes are. If each artifact is organized differently, those tools have to guess—and may fail when a file or field is missing.

Specifications make those expectations explicit, so new skills, scripts, and automations can work with artifacts produced by existing skills.

They also provide a foundation for viewers and editors where people can browse, review, and change artifacts. The goal is to make collaboration with agents on these artifacts as straightforward as working together in other tools. A documented format gives those interfaces a reliable way to read and update the same content agents use.

## Versions and upgrades

Artifact formats will evolve. Each specification has a version, recorded on the artifact as `specVersion`, so a tool can identify the format it receives and determine whether it supports it.

Keeping a document for each version preserves how the format has changed over time. When a new version changes the structure or required fields, upgrade scripts can bring older artifacts into the new format and update their `specVersion`.

Each artifact type has its own directory containing the current version, a specification document for each version, and an `upgrades/` directory for migration scripts.
